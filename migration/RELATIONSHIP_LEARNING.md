# 持续关系态度评估

AstrBot 迁移后旧 `qq-relationship` 文件不再随聊天更新。管理台过去仅显示
这些历史分数，原生关系表又没有已采纳记录，导致真实互动与评分长期脱节。

现由兼容插件后台任务读取同一真实账号的双向对话，对好感、信任、熟悉度
和交流态度做有依据的估计，写入共享人物 SQLite 的
`relationship_assessments`。群聊、私聊及管理台读取同一结果；旧档案保留。
它是可解释的对话估计，不是情感测量或亲密关系认证。

- 只有具有对方输入和 QQ 已确认送达回复的消息轮次参加评估。
- 初次至少两轮；以后有新回复且距上次至少30分钟，或至少六轮新回复且
  距上次至少5分钟，才进入评估。每轮扫描最多两个账号，每60秒扫描一次。
- 调用现有低价优先聊天路由，保留其模型顺序与5分钟恢复探测；不逐条消息
  调用评估模型。输入最多40条记录、12000字符，聊天提示只取精简态度字段。
- 必须引用真实记录 ID，包含双方发言及至少一条未评估的新回复；伪造证据、
  非法分数、模型故障均不更新。失败后持久化退避至少5分钟。
- 首次相对有效旧分数最多变动20，后续每次最多变动5；可升可降，不能刷消息
  自动满分，也不能用管理员身份或聊天命令指定分数。
- 记录评估时间、依据、游标和最近12次变化；事务校验游标防止过时任务覆盖。
- 后台任务不阻塞聊天和健康心跳；`jiangsheng-health.json` 中的
  `relationshipLearning` 及审计的 `relationship_assessment_failed` 可排查故障。

管理台区分旧历史估算和当前对话估计，展示态度、依据、时间及最近变化。
指定受限档案的管理员访问检查仍在 HTTP 服务端执行。

验证：57项迁移回归、123项维护回归、JS语法检查通过；生产云端评估经真实
历史记录校验后持久化，生产档案 helper 回读一致，QQ与陪伴插件健康。
