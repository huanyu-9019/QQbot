# 人物记忆的依据与展示

人物按真实 QQ 账号识别。同一账号的群聊、私聊和不同群来往共用；昵称、引用与被 @ 的人不能代替发言者身份。

管理台与聊天使用同一份 `runtime/data/legacy/qq-user-memory` 和同一套 `policy.person_portrait/profile_context` 清理规则。读取时去重、排除明显问句碎片，把交流习惯、作息与边界分开；保留原始文件，不把清理结果伪装成新获得的事实。群内被提及者的称呼查询仍限于称呼，完整人物上下文只归当前发言账号。

## 三种不同的依据

- **迁入资料线索**：旧提取没有逐条消息来源。保留其中的称呼、关系和有效偏好，明确标为迁入记录；不把“情侣”标成刚确认，也不因旧评分较低把已有亲密关系降为陌生人。当前明确更正和有来源的新记忆优先。
- **实际来往**：`jiangsheng-person-memory.sqlite3` 保存带真实账号、场合、时间和发言方的记录。页面展示最早及最近片段和实际收录消息数；这不是精选共同经历或已确认事实。机器人当年的回答也可能错误，不用它来认证关系。
- **新系统记忆**：读取 Companion 原生数据库的身份绑定，以及当前人格、bot、installation 下的 active self memory 和 adopted relationship。撤回、归属其他人的、第三方 subject 的资料不作为该人的事实。展示来源条数及保存时间；查询失败与尚无记忆分别显示。

旧关键词关系算法的熟悉度、好感度、信任感、封顶100的次数及“关系阶段变更”不再作为当前关系和共同经历展示。原数据保留用于诊断。时间同时兼容 Unix 秒、毫秒和 ISO 字符串。

## 聊天与后续维护

统一个人记忆读取成功时，不再第二次注入同一份个人偏好和私聊摘要；读取失败仍保留旧资料回退。发言者绑定中的旧关系同时携带 `relationships_basis=legacy_unverified`。真实对话仍可检索，不靠增大好感分修复关系。

本次没有把旧偏好自动认证为新记忆，也没有新建另一个并行的模型总结器。上线核查时原生结构化记忆及关系记忆为空，因此页面必须诚实展示空状态。后续若修复原生记忆采纳链，应检查真实写入、来源、更正及撤回，不能仅根据 UI 出现内容就报告学习成功。

## 验证与回退

`python -m unittest discover -s migration/tests` 包含脏偏好、重复注入、旧关系冲突、账号归属、只读查询和 helper→HTTP 投影回归。浏览器使用真实生产静态文件与合成资料验证日期、归属和 HTML 转义；不向 QQ 联系人发送测试消息。

生产发布先备份源文件、旧档案与两个记忆数据库；部署文件统一 LF，避免 Linux shebang 因 CRLF 无法执行。持有 responder 发布锁，检查源文件哈希并运行服务器暂存测试后发布；新 heartbeat 必须确认 QQ、Companion 和共享记忆就绪，失败恢复快照。管理台和 Codex 维护目录同步同一份实现与测试。


## 被提及的人与发言者

@是结构化消息中的账号引用，不等于正在对这个人说话。`@某人 是谁`可作为向江生询问第三人的候选，`@某人 你是谁/想我了吗`仍保护对方的直接对话。只从实际At/OneBot组件取得账号，不从用户手打的@文本推断身份。入站保存组件以免后续raw_message变化丢失引用；引用关系与发言者分别绑定。

查询当前群名片时限定同一个群和账号，最多5个并发查询、每个3秒上限；失败可用本轮At昵称或同账号旧群名片。简单单目标身份问题可直接依据昵称和已有称呼回答，不能因不知道现实身份就否认看得出被@的是谁，也不能把昵称认证为真实姓名或关系。解析失败记录为mention_target_unresolved供服务器维护评估；directedToBot避免把正常介绍第三人的回答错判为抢答。
